i

Power flow solves the network's steady-state AC power balance — every bus's complex power injection must equal what its neighbors deliver through the network's impedances — via Newton-Raphson iteration, to get every bus's voltage, angle, and power flow at the DER dispatch and load levels currently set. It's the foundation everything else in this tool is built on: modal analysis linearizes around this operating point, and EMT simulation runs around it too. Useful for: checking a dispatch is even feasible (voltages in range, no overloaded lines) before asking anything about its dynamics.

Run power flow to see the network diagram (colored by voltage magnitude) and results.

i

Modal analysis linearizes every component (each generator/converter's own dynamics, every line, node, and load) around the power-flow operating point into one closed-loop state matrix, then eigen-decomposes it. Each eigenvalue is one natural oscillation mode of the network — its frequency, damping ratio, and (via participation factors) which physical states actually drive it. Useful for: the question every power-system stability study starts with — is this generation mix and dispatch small-signal stable, and if not, which control loop or machine is responsible?

Run modal analysis to see the eigenvalue map and mode table.

i

Time series re-solves power flow across several load/dispatch snapshots in a plain loop — no dynamics, no coupling between snapshots, just independent steady-state solves. Useful for: a quick, cheap look at how bus voltages and line loading shift across an operating range (e.g. light to peak load) without the cost of a full time-domain simulation for every point.

Run the sweep to see bus voltages at each load level.

i

Network is an interactive one-line diagram of the topology itself — buses, lines, transformers, and DER units laid out automatically from the graph structure, no dynamics or results involved. Click any element to inspect its own electrical parameters (impedance, length, control-loop tuning...). Useful for: building a mental picture of what's actually connected to what before reading any results, and for spotting a wiring mistake in a hand-built network at a glance.

EMT simulation integrates the network's actual nonlinear differential-algebraic equations forward in time — a coupled Newton solve at every step, not a linearized approximation — after perturbing one state (or stepping one input) away from its operating point. This is the ground truth a linearized modal analysis is only ever an approximation of. Useful for: seeing a real transient (does a speed deviation actually settle, and how does it actually look, not just "is the linearization stable"), and for checking how far modal analysis's small-signal assumption still holds for a larger disturbance.

Traces step by step as it computes — can take significantly longer than the default run.

EMT time-domain simulation: perturb a state away from its operating point and integrate the full nonlinear network model to see whether — and how — it recovers.

Documentation is the full physics and architecture reference this tool is built from — the same equations (as real LaTeX), methodology, and module-by-module narrative that describe the code itself, not a separate simplified explanation. Useful for: understanding *why* a result looks the way it does — what a state actually represents, what a control loop's gains were tuned for, or what a tab's underlying method assumes and doesn't.
